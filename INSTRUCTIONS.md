## Changes needed for the hackathon

Add a bounded Meta execution lane and evaluation runner around one declared workload. This is an experiment-specific addition; rewriting the whole factory is unnecessary.

1. **Freeze the input.** Select the probe and declare the evaluated module or full-probe scope. Capture source versions, the V1 learning objectives, coverage, input files, and fresh hashes. A module demonstration must be labelled as that scope.
2. **Execute through Meta.** Use a documented Meta endpoint or supported Meta openweights provider. Record the real provider, model, prompt, input hashes, raw response, usage, elapsed time, failures, and retries. Schema compatibility must be tested against the actual endpoint.
3. **Produce deeper teaching.** Generate explanations of why and how, worked or contextual examples, misconception correction, and aligned application questions. Preserve authoritative facts, qualifiers, exceptions, quantities, and source links. Additional length alone does not satisfy instructional depth.
4. **Verify independently.** Freeze correctness and acceptance checks before generation. Combine schema, coverage, ID, and answer checks with source-grounded factual review. Keep a generating model from approving its own result. Supplementary model judgments must identify their model and rubric.
5. **Present and compare.** Build an isolated preview of the candidate lesson, cards, and assessment, with a compact V1 comparison. Preserve provenance so a reviewer can distinguish reference material, generated output, and human corrections.

The first Meta qualification task may use Worker 04. Passing that task establishes a bounded integration result; the submitted proposal also needs a working instructional experience and evaluation of its depth and assessments.

## Experiment design

Compare the V1 reference and V2 candidate on matched learning objectives, source coverage, and declared scope. Score factual errors, missing coverage, explanation usefulness, worked examples, misconception handling, assessment alignment, and answer/rationale agreement. Blind the qualitative comparison where practical.

A V1-to-V2 comparison measures the change in the overall workflow. A claim that Meta outperforms another model needs a separate control using the same V2 task, inputs, prompts, budget, and acceptance criteria. Add that control only if it serves the question and fits the rules and time budget.

Record model tokens, provider charges when available, latency, retries, review effort, human decisions, manual corrections, and final output hashes. Report measured instructional ratings as ratings. Improved learner understanding requires learner evidence.
